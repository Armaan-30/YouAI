YouAI — iOS priority and status plan

Audit date: 16 October 2026 · main commit 5d3aea2e396e1d981c0e4963788f443a2ad5e32c

Current state: architecture documented; implementation not started in this repository. The complete GitHub tree contains README.md and LICENSE only. No iOS app, inference integration, tests or backend was present in the audited commit. This report is a proposed build plan, not a claim that features have been built.

What the README establishes

The design specifies voice and text input sharing an orchestration layer, conversation context, a local LLM, optional local document retrieval, displayed answers, spoken output and local conversation storage. It permits native UI and three deployment modes: fully on-device, phone plus local computer, and an explicitly configured hybrid fallback. Wake-word activation is future scope; a task-execution subsystem is not yet specified. Audited README.

Architecture for your app

Circular button OR consent-based foreground “Hey You” → Audio capture + voice activity detection → Whisper speech-to-text → Normalized prompt ← secondary text input → Orchestrator ← conversation history + optional local RAG passages → Local LLM → Answer text → transcript + text-to-speech → speaker/headphones For an action: Model proposes a structured tool call → validate parameters, permissions and confirmation → execute an allowed iOS integration → obtain result receipt → update conversation → speak actual result

Proposed stack: SwiftUI, AVAudioSession/AVAudioEngine, whisper.cpp, llama.cpp with a benchmark-selected quantized Qwen or Gemma model, native AVSpeechSynthesizer, and SQLite. Use a separate on-device keyword detector for “Hey You.” Pick its runtime/model after license, battery and accuracy evaluation. These choices preserve the README; final model sizes are deliberately undecided until device measurements. whisper.cpp and llama.cpp are candidate runtimes.

UI: One dominant circular button and a short status label. Tap starts listening; tap again ends recording or cancels current work. Use explicit listening, transcribing, thinking, confirming, executing, speaking and error states. Put transcript, typing, replay, document sources and settings in a secondary sheet. Keep confirmation prompts visible when required. This preserves the README’s text interaction and playback controls.

Important iOS boundary

Build foreground “Hey You” first. Do not assume an ordinary app can replace Siri’s system wake phrase or continuously wake itself from suspension/termination. Apple controls background runtime; background modes must serve their intended purpose. A temporary user-started background recording session requires a separate feasibility and review assessment, not a promise of perpetual listening. Siri/Shortcuts and supported system controls can provide additional entry points through App Intents. Background execution, review guideline 2.5.4, App Intents.

Task boundary: “Does tasks” means explicit integrations that iOS and the connected service permit. The model is not granted arbitrary control over other apps. Proposed first tasks are reminders, calendar events and notes stored inside YouAI. Every tool must return a real result; the assistant must not claim success from generated text alone.

Milestones and acceptance gates

  1. Feasibility: choose supported devices; validate local models and activation; establish an Xcode build and physical-device testing.
  2. Working assistant: finish P1. Tap or say “Hey You” in the foreground, speak naturally, receive a local spoken answer, retain context, execute an allowed confirmed action and interrupt reliably.
  3. Complete selected architecture: add document import/RAG with sources, system entry points, offline verification, performance tuning and accessibility.
  4. Release: pass device regressions, TestFlight feedback and App Store requirements. Optional computer/remote modes do not block the on-device release.

Decisions needed before implementation

Minimum iPhone and iOS version; access to a Mac with Xcode; first supported languages; the exact first task list; and whether background listening is a must-have or foreground activation plus system shortcuts is acceptable. The present Windows workspace cannot establish successful native iOS builds or on-device performance. A delivery date would be speculative before these choices and the feasibility benchmark.

Quality evidence to collect: speech accuracy on representative recordings, wake-word false accepts/misses, p50/p95 response latency, peak memory with both models loaded, sustained thermal/battery behavior, tool execution correctness, interruption recovery and complete offline operation after required assets are installed. Set numeric acceptance targets in P0; none are represented as measured here.
